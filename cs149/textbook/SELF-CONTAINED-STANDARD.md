# Self-contained 中文教材编写标准

**适用范围：** cs149/textbook/ 下的正式教材正文。cs149/notes/ 可以保持速查风格，但不得拿速查笔记的短篇幅标准评估教材正文。

## 核心要求

读者应当能**只打开一章 Markdown**，不观看视频、不打开 Slides、也不阅读其他网站，就能完成本章的理论学习和基本自测。

“自包含”不是复制所有外部材料，也不是无限补充先修学科。它意味着清楚说明最小先修假设，并在本章提供所有理解本章核心推导所需的概念、变量、图示、步骤与例子。

### 发布前的八项检查

1. **先修要求：** 章首写明默认读者已知什么（如基本 C++/矩阵乘法）；关键但非默认的概念在第一次出现时解释。不能只说“先看上一讲”。
2. **完整因果链：** 按“问题 → 直觉 → 模型 → 推导 → 结果 → 反例/边界”叙述。每个新公式先定义变量、单位和假设，再给完整的推导或可独立复算的算例。
3. **独立的图解：** 用原创的文字图、Mermaid 或表格表达依赖图/内存层级/数据流。外部 Slides 只是补充参考，不是理解所必需的唯一图。
4. **可复算的例题：** 至少一个带具体数字、逐步计算和正确结果的 Worked Example；明确区分教学假设与课堂实测。
5. **实践可执行：** 核心代码必须完整、给出语言与环境、运行/编译命令、输入/预期输出、正确性检查。如果只是伪代码，必须明显标注，并给出可运行的最小版本或手工推演。
6. **无硬件亦可理解：** CUDA/HPC 章节允许 GPU 为实操前提，但必须包含一个无需 GPU 的纸笔/CPU 推演，使读者不会因为缺少硬件而无法学习概念。
7. **练习与答案：** 每章包含概念题、计算题和工程思考/实验题，关键问题给参考答案或推导线索，避免强迫读者去外部搜索标准解法。
8. **出处与限制：** 正文完整解释知识点，来源链接放最后以便核查；注明哪些说法来自课程、哪些是作者推导、现代 AI Infra 扩展或尚未核实的口述片段。严禁将自动字幕直接当作校对后的原话。

## Markdown / GitHub 兼容约定

- 公式使用 GitHub 支持的块公式写法：单独两行双美元符包围，例如下方的 Markdown 源码示意。
- 不用独立行以减号或加号开头来拼公式，以免被解析成列表；短公式在一个数学块内写一行，复杂公式用 LaTeX aligned 环境。
- 可运行代码使用带语言的代码围栏；伪代码明确写“不可直接运行”。
- 图表只使用 GitHub 原生支持的 Markdown / Mermaid / 纯文本；关键知识不能仅寄托于远程图片。
- 跨章链接只作“延伸阅读”，不应是本章缺失推导的替代品。
- 不要将官方 PDF、完整讲课字幕或大段课件翻译直接搬入公开仓库；应自行组织原创教学文本，并保留外部来源链接。

块公式源代码示例：

~~~markdown
$$
T_P = T_{\mathrm{compute}} + T_{\mathrm{communication}}
$$
~~~

## 发布质量分级

| 状态 | 标准 |
| --- | --- |
| outline | 只有大纲或章节目录，尚不可用于自学 |
| draft | 有核心概念，但算例、独立图解或实践尚不完整 |
| self-contained draft | 单章理论、算例、练习都可独立阅读；代码有明确的验证边界 |
| reviewed | 内容做过来源对照、关键计算与代码验证、GitHub 渲染/链接检查 |

**Self-contained** 与 **Transcript 已完整核对** 是两个独立维度。一个章节可以自包含但仍需补充字幕核验；也不能因为参考材料很多就称其为完整教材。

## 验收问卷（自测）

试着从陌生读者视角回答：

- 不打开 PDF，是否能复述本讲核心结论、解释每个符号？
- 能否根据教材独立算出 Worked Example 的答案？
- 没有课程视频，能否辨认图里的每个计算阶段、内存路径和依赖？
- 本章所有“运行以下代码”是否都给出完整代码和预期结果？
- 没有 NVIDIA GPU 时，是否仍能完成至少一项核心概念练习？
- 理论结论是否分别注明了假设、适用范围与失败条件？
- 栏目中的外部链接是否仅用于验证/延伸，而不是暗示“重要部分请看外部材料”？
- 引文、实测、自动字幕、作者推导是否分别标明？

没有通过的项目，应在章节开头标注仍属于 draft，不能以“完整教材”对外描述。
